# فليكس — نظام إدارة الأملاك العقارية

نظام لإدارة العقارات والوحدات والملاك والمستأجرين وعقود الإيجار وتحصيلها، بواجهة عربية من اليمين إلى اليسار. يخدم مكاتب إدارة الأملاك التي تدير عقارات غيرها، والمُلّاك الذين يديرون عقاراتهم بأنفسهم.

## ما يغطّيه

| المجال | التفصيل |
|--------|---------|
| العقارات | المباني والوحدات، الصكوك، الموقع على الخريطة، العدّادات، جهات الاتصال، الصور |
| الملاك | بياناتهم، اتفاقيات الإدارة وعمولاتها، كشوف الحساب، سندات التوريد، وبوابة دخول اختيارية |
| الإيجارات | العقود وجداول أقساطها، التجديد، الفسخ، وإخلاء الوحدات |
| التحصيل | تسجيل الدفعات، الترحيل التلقائي للفائض، الإحالة إلى ناجز، وديون المستأجرين السابقين |
| المستندات | الفواتير وسندات القبض والصرف والتوريد — تُلغى ولا تُحذف |
| الإدارة | الموظفون والأدوار والصلاحيات، طلبات الموافقة، وسجل العمليات |

## قواعد يقوم عليها النظام

- **لا يُسجَّل ريال بلا سند.** التحصيل ومستنداته يُكتبان في معاملة واحدة؛ فسندٌ يتعذّر إصداره يترك الدفعة غير مسجَّلة.
- **المستند المالي يُلغى ولا يُحذف.** يبقى رقمه وسببُ إلغائه ومن ألغاه.
- **حالة الوحدة يقولها عقدها.** تصير مؤجرة بكتابة العقد، ولا تُخلى إلا بقرار صريح.
- **الدين يلاحق المستأجر لا الوحدة.** لا تُحبس شقة صالحة للتأجير بسبب دين سابقها.
- **الإجراءات الحسّاسة تمرّ بموافقة.** الموظف يرفع طلباً، ومدير النظام يقرّر.

## التشغيل

```bash
cp .env.example .env         # واضبط AUTH_SECRET
npm install
npx prisma migrate deploy    # إنشاء قاعدة البيانات
npm run db:seed              # الأدوار الأربعة، وحساب مدير، وبيانات تجريبية
npm run dev                  # التطوير على المنفذ 3000
```

`db:seed` **للتطوير وحده**: يزرع برجاً ومستأجراً وعقداً تجريبية بـ `create`، فتكراره
يكرّرها. ما تحتاجه نسخة حقيقية هو `db:bootstrap` — الأدوار وحساب المدير فقط، ويُعاد
تشغيله بلا أثر.

للإنتاج:

```bash
npm run build && npm run start:deploy
```

### متغيّرات البيئة

| المتغيّر | الغرض |
|----------|-------|
| `DATABASE_URL` | مسار قاعدة SQLite. محلياً `file:./dev.db`؛ على الخادم مسار مطلق على القرص المُثبَّت |
| `AUTH_SECRET` | مفتاح توقيع الجلسات — `openssl rand -base64 32` |
| `AUTH_URL` | العنوان الذي يراه المتصفّح. يلزم خلف وسيط |
| `UPLOADS_DIR` | مجلّد المرفقات. اتركه محلياً؛ على الخادم وجّهه إلى القرص المُثبَّت |
| `ADMIN_EMAIL` · `ADMIN_PASSWORD` | حساب المدير الأول. يُقرآن عند أول إقلاع ثم يُحذفان |

`AUTH_TRUST_HOST` لم يعد يلزم: النظام يثق بمضيفه في `src/auth.ts`، لأن إغفاله كان يترك
صفحة الدخول تظهر سليمة ولا يدخل أحد، والسبب لا يُرى إلا في سجلّ الخادم.

## النشر

الحالة والشيفرة لا تعيشان في المكان نفسه. حاوية المنصّة تُبنى من جديد مع كل نشر، فقاعدة
SQLite والمرفقات إن بقيا داخلها ضاعا مع أول دفعة إلى `main`. **قرص مُثبَّت، وإلا فلا نشر.**

1. خدمة جديدة من هذا المستودع. الملفّان `railway.json` و `nixpacks.toml` يكفيان: بناء
   بـ Nixpacks، وبدء بـ `npm run start:deploy` الذي يُرحّل القاعدة ويُهيّئ الأدوار قبل أن
   يخدم أي طلب.
2. **قرص مُثبَّت على `/data`.** هذه هي الخطوة التي بدونها يعمل كل شيء ثم يختفي.
3. المتغيّرات:

   ```
   DATABASE_URL   = file:/data/dev.db
   UPLOADS_DIR    = /data/uploads
   AUTH_SECRET    = <openssl rand -base64 32>
   AUTH_URL       = https://<النطاق>
   ADMIN_EMAIL    = <بريد المدير>
   ADMIN_PASSWORD = <كلمة مرور مؤقّتة>
   ```

   `PORT` تحقنه المنصّة، ولا يُضبط يدوياً — لكن **منفذ النطاق** يُضبط: إن أشار النطاق
   إلى منفذ غير الذي تحقنه المنصّة أعطت الحافة 502 بلا سطر واحد في سجلّ التطبيق،
   لأن الطلب لا يبلغه. وهذا بعينه ما أوقف `dashboard.flexksa.co`: النطاق على 8000
   والتطبيق يسمع على 8080.

   و `AUTH_URL` ليس تزيّناً: بدونه يُصادَق المستخدم ثم يُعاد توجيهه إلى
   `localhost` والمنفذ الداخلي — عنوان لا يفتح.
4. النطاق: أضفه إلى الخدمة **أولاً** ودع المنصّة تُصدر شهادته، ثم وجّه سجلّ DNS إليها.
   سجلّ يشير إلى خدمة لا تطالب بالنطاق يعطي 502 من الحافة، بلا أثر في سجلّ التطبيق —
   لأن الطلب لا يبلغه أصلاً.
5. أول دخول يطلب كلمة مرور جديدة، لأن الأولى مكتوبة في إعدادات الخدمة. بعده احذف
   `ADMIN_EMAIL` و `ADMIN_PASSWORD`.

**نسخة واحدة من الخدمة، لا أكثر.** قاعدة SQLite ملفّ على قرص، وكاتبان عليه من حاويتين
يفسدانه. التوسّع أفقياً يعني الانتقال إلى Postgres أولاً، لا زيادة النسخ.

## النسخ الاحتياطي

```bash
scripts/backup.sh            # لقطة متّسقة للقاعدة مع المرفقات
scripts/restore.sh <ملف>     # الاستعادة
```

وللمدير زرّ تنزيل نسخة من **بيانات المنشأة** داخل النظام.

## الدخول وحمايته

خمس محاولات فاشلة تُغلق الحساب ربع ساعة، ثم نصف ساعة، فساعة، بسقف أربع ساعات — ويُصفَّر العدّاد بأول دخول ناجح. وعشرون محاولة فاشلة من عنوان واحد خلال ربع ساعة تُغلق العنوان نفسه. والمحاولات الفاشلة تظهر في **سجل العمليات**.

المدير يعيد تعيين كلمات مرور الموظفين والملاك من داخل النظام. أما كلمة مرور المدير نفسه فلا أحد فوقه، ولها طريقان:

```bash
npm run admin                                   # عرض حسابات المدير
npm run admin -- someone@example.co             # إعادة تعيين كلمة مرور مدير موجود
npm run admin -- someone@example.co "الاسم"     # إنشاء مدير ثانٍ
```

تُطبع كلمة مرور مؤقتة مرة واحدة، ويُجبر حاملها على تغييرها عند أول دخول، ويُرفع عن الحساب قفل المحاولات.

**يُنصح بمديرَين** لا واحد: أحدهما يعيد تعيين الآخر من داخل النظام دون الحاجة إلى الخادم.
